# WorkflowTool — repo conventions

AI-native workflow automation backend (n8n/Zapier-style: trigger → nodes → actions, with Claude calls as a first-class node type). This file is the fast-start reference for working in this repo — for full architecture rationale and the phased roadmap, see `PLAN.md` and `phase1Plan.md` one directory up, in `AiWorkflowTool/`.

## Stack

- **Backend**: FastAPI (async)
- **DB**: PostgreSQL, accessed via SQLAlchemy 2.0 (async, typed declarative style) + `asyncpg`
- **Migrations**: Alembic, configured for async engines (`alembic init -t async`)
- **Config**: `pydantic-settings`, reading from `backend/.env` (never committed — see `.env.example`)
- **Local infra**: Postgres + Redis via `docker-compose.yml` (Redis is provisioned now but unused until the async execution engine, Phase 3)

## Project layout

```
backend/
  app/
    core/            # Settings (pydantic-settings), config.py
    datastore/
      session.py      # async engine, session factory, Base
      models/          # one file per table — all subclass Base
    main.py            # FastAPI app entrypoint
  alembic/              # migrations; env.py imports app.datastore.models
                        #   so Base.metadata sees every table
  requirements.txt
  docker-compose.yml
```

## Local dev setup

```bash
# from WorkflowTool/
docker-compose up -d                       # Postgres + Redis

# from WorkflowTool/backend/, with the venv active
python -m venv ../.venv                    # one-time
../.venv/Scripts/Activate.ps1              # Windows
pip install -r ../requirements.txt
python -m uvicorn app.main:app --reload
python -m alembic upgrade head             # apply migrations
```

## Conventions

- **Every model subclasses `Base`** from `app.datastore.session` and lives in `app/datastore/models/`, one file per table. Add the import to `app/datastore/models/__init__.py` so it registers on `Base.metadata` — Alembic autogenerate can only diff what's been imported.
- **UUID primary keys** on every table (`UUID(as_uuid=True), default=uuid.uuid4`), not auto-incrementing integers.
- **Every domain table is scoped by `workspace_id`**, not `user_id` — this is what lets multi-user workspaces be an additive feature later instead of a schema migration.
- **Credentials are write-only.** `credentials.encrypted_value` (Fernet-encrypted) is never returned by any API response — accept plaintext on create, return metadata only, ever after.
- **Review autogenerated migrations before applying them.** `alembic revision --autogenerate` produces a draft, not gospel — check FK ordering, enum reuse, and `ondelete` behavior before `alembic upgrade head`.
- **Node plugin pattern** (from Milestone 1.2 onward): every node type is a small class + a Pydantic config model, registered via decorator, so `GET /node-types` can generate frontend config forms without per-node frontend code. See `phase1Plan.md` §6.

## Known gotcha (don't repeat this)

`requirements.txt` must be regenerated via `pip freeze` from the **actual project venv** (`WorkflowTool/.venv`), never from a global or unrelated Python environment. This bit us once already — an earlier `requirements.txt` was frozen from a different environment entirely and came in UTF-16 (a PowerShell `>` redirect artifact), bloated with ~180 irrelevant packages. If a `pip freeze` looks larger than ~25 lines, something's wrong — check which Python ran it.

## Testing

Tests run against a real Postgres instance (the dockerized one), not SQLite — the schema uses Postgres-specific types (`jsonb`, native enums) that SQLite can't validate.

## Git workflow

- Feature branches per unit of work, named for **what the branch does**, not internal planning-doc jargon (e.g. `feature/db-models-and-first-migration`, not `milestone-1.1`) — branch names should be self-explanatory in `git log` without needing `phase1Plan.md` open.
- No direct commits to `master`. Merge via PR.
- Before creating a new branch for the next chunk of work, confirm its prerequisites actually landed on `master` (`git show master:<path>` is a quick check) — a branch cut too early is missing files it needs.
